# SECURITY — модель угроз и остаточные риски

`claude-pod` уменьшает ущерб от скомпрометированного/зарвавшегося агента, но **не является
абсолютной песочницей**. Ниже — от чего защита есть, а от чего нет. Читать перед использованием на
чувствительных машинах.

## От чего защищаемся (и как)

| Угроза | Механизм |
|---|---|
| Утечка **токена/ключей основного GitHub-аккаунта** | они не пробрасываются: нет `~/.ssh`, `~/.config/gh`, `GH_TOKEN`/`*_API_KEY` в контейнере |
| Доступ агента к **другим репозиториям** | GitHub-**deploy key** привязан к одному репо; на `down` отзывается |
| **Копирование** приватного ключа из контейнера | ssh-agent forwarding: ключа нет на диске контейнера (только сокет) |
| Порча **токена Claude** (`~/.claude/.credentials.json`) | смонтирован **read-only** |
| Действия от **root на хосте** | непривилегированный пользователь (uid/gid хоста), podman rootless |
| Замусоривание/повреждение **системы хоста** | ФС-изоляция контейнера; виден только каталог проекта и `~/.claude` |

## Остаточные риски (важно)

1. **Токен `~/.claude` внутри контейнера ЧИТАЕМ.** `read-only` защищает от *записи/порчи*, но не
   от *чтения*. Мы **не** включаем сетевой egress-фильтр, поэтому вредоносный код/промпт-инъекция
   теоретически может **прочитать и выгрузить** OAuth-токен Claude наружу. Митигации: не запускать
   на недоверенных репозиториях без присмотра; при необходимости — внешний firewall/allowlist;
   ротация токена. (Опциональный `--firewall` — в roadmap.)
2. **Проброшенный проект пишется на хост.** Всё, что агент меняет в каталоге проекта, сразу
   попадает на хост (это by design для бесшовной работы). Правки вне проекта — заблокированы.
3. **Deploy key с правом записи (`--key rw`, по умолчанию)** позволяет **push, в т.ч. force-push**
   в *этот* репозиторий. Для аудита недоверенного кода используйте `--key ro` или `--key none`.
4. **DinD (`--docker`/авто) = фактически root на хосте.** Доступ к docker-сокету позволяет поднять
   привилегированный контейнер и выйти на хост. Включайте только для доверенного кода; авто-режим
   печатает предупреждение.
5. **`--net-host`** убирает сетевую изоляцию контейнера (общая сеть с хостом). Удобно для прокси,
   но контейнер видит локальные сервисы хоста.
6. **`--inherit-env`** расширяет поверхность: пробрасываются все переменные, кроме денилиста
   (`GH_TOKEN`/`GITHUB_TOKEN`/`*_API_KEY`/`*_SECRET`/`*_TOKEN`/`*_PASSWORD`/`AWS_*` и т.п.).
   Если ваш секрет назван нестандартно — он может просочиться. Предпочитайте точечный `--env`.
7. **`--key-file`** (фолбэк) кладёт приватный ключ файлом в контейнер (ro) — его можно скопировать
   изнутри до отзыва. Слабее ssh-agent; используйте только когда агент недоступен.
8. **Компрометация хоста/`gh`** вне модели: `claude-pod` доверяет хостовому `gh` и ssh-agent.

## Рекомендации

- Недоверенный код → `--key ro` или `--key none`, без `--docker`, без `--net-host`.
- Не оставляйте контейнеры «висеть»: `cpod down` отзывает ключ и чистит состояние.
- Проверяйте отзыв ключей: `gh api /repos/<owner>/<repo>/keys`.
- Для jobs без присмотра рассмотрите внешний egress-allowlist на уровне сети/хоста.
